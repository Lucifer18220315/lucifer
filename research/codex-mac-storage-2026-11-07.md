# Codex на Mac: локальное место при облачной работе

Дата: 2026-11-07. Пользователь сообщил, что место на диске Mac уменьшается именно при работе в этом чате, уточнил приложение **Codex**, выполнил предложенную команду `du` в Терминале Mac и прислал скриншот. Просмотрен скриншот, переписаны размеры. Имя пользователя из абсолютных путей в базу не переносится. Сам скриншот отдельным файлом не выгружен.

Родительские каталоги включают вложенные: **не складывать** `sessions` с `~/.codex` как независимые статьи, `Default` с родительским кэшем или `Default/artifact-sessions` с родительским Application Support. Три независимых корня — `~/.codex`, Application Support/Codex и Caches/Codex — занимают приблизительно **11,4 GB** по округлённым показаниям. Это оценка, не точный побайтовый подсчёт. Полный состав 9,6 G на скриншоте не раскрыт.

Наличие существенных локальных данных Codex подтверждено. Точный прирост во времени и доля **конкретно этого чата** не измерены; одного снимка размеров для этого недостаточно. `sessions` может содержать несколько сессий. Содержимое сессий, баз данных и секретов не читалось.

## Почему Git и облако этого не исключают

Git сохраняет версионную историю проекта. Облачный исполнитель хранит рабочую копию, зависимости, рендеры и временные файлы на сервере. Приложение Codex на Mac отдельно хранит локальные данные, сессии, кэши и артефакты; облачное выполнение команд не означает отсутствия этих данных на клиенте.

В этой задаче сервер подтверждён как Linux, cwd `/workspace`; свободно около 57GB в момент проверки. История Git выбранного проекта занимала 8,58 MiB на сервере до нового коммита. Эти значения не описывают диск Mac и не являются замером его кэша.

Прежнее категоричное объяснение помощника было исправлено: нельзя обещать, что работа в облаке вообще не занимает место на Mac. Большой объём локальных данных Codex не следует приписывать Git или CapCut без соответствующего замера.

## Следующая безопасная проверка

Сначала найти крупные сессии **без чтения их содержимого**, в обычном Терминале Mac:

```bash
find "$HOME/.codex/sessions" -type f -exec du -h {} + 2>/dev/null | sort -h | tail -n 10
```

Отдельно посмотреть крупные файлы непосредственно в корне, если сумма видимых подпапок не объясняет весь объём:

```bash
ls -lhS "$HOME/.codex" | head -n 15
```

Для проверки роста повторить измерение размеров через известный интервал работы с одним чатом и сравнить время/размер файлов. Это локальные команды пользователя; помощник не имеет инструментов доступа к его Mac. Вывод не должен включать содержимое JSONL, конфиги, токены или базы данных.

## Что можно очищать отдельно

Первый понятный кандидат — **только** `~/Library/Caches/Codex`, около 1GB. Если пользователь решит чистить: после завершения работы полностью закрыть Codex через Cmd+Q, в Finder открыть родительскую папку `~/Library/Caches`, переместить только `Codex` в корзину, запустить приложение и проверить работу. Место освободится после удаления из корзины; кэш может создаться повторно. Это инструкция, **очистка не выполнялась**.

Не удалять целиком `~/.codex`, `sessions` или Application Support/Codex: там могут быть история, настройки и другие нужные данные. Историю отдельных сессий сначала идентифицировать/сохранить; произвольная очистка или сброс приложения не поручались. Базы данных не изменялись и не уплотнялись.

## Изменение процесса помощника

Промежуточные кадры, HTML и подробные отчёты оставлять файлами на сервере; в чат выводить краткие итоги и небольшие контрольные раскладки только по необходимости. Не выводить без нужды целые HTML/JSON или десятки полноразмерных кадров. Проверка видео по-прежнему выполняется; меньший вывод не означает отказа от проверки. Это уменьшает объём новых материалов в диалоге, но не обещает автоматического освобождения уже занятого места или остановки роста всех локальных данных Codex.
